# Opening Trainer

Lichess에 저장한 개인 오프닝 연구를 챕터별로 반복 훈련하고, 실제 게임 분포를 상대로 자유롭게 오프닝을 연습하는 앱입니다. Windows EXE와 iPhone에 설치할 수 있는 PWA를 함께 제공합니다.

## iPhone·브라우저 PWA

배포 주소: <https://najdorf02.github.io/opening-trainer-pwa/>

iPhone에서는 링크를 **Safari**로 연 뒤 `공유` → `홈 화면에 추가` → `추가`를 누르면 일반 앱처럼 실행할 수 있습니다. 처음 한 번은 다음 순서로 준비합니다.

1. 홈 화면에서 `Opening Room`을 엽니다.
2. `Lichess 연결`을 누르고 `SaturdayCthuns` 계정으로 연구 읽기 권한을 승인합니다.
3. 앱으로 돌아오면 첫 연구 동기화가 자동으로 시작됩니다. 이후에는 연구를 수정한 뒤 `연구 동기화`를 누릅니다.

Lichess 연결은 설치 전 Safari 탭이 아니라 **설치 후 홈 화면 아이콘으로 연 앱 안에서** 시작해 주세요. 첫 실행과 첫 동기화에는 인터넷 연결이 필요합니다.

비공개 연구를 공개로 바꿀 필요가 없습니다. GitHub에는 앱 코드만 올라가며 Lichess 토큰, 비공개 PGN, 훈련 캐시는 각 기기의 브라우저 저장소(IndexedDB)에만 보관됩니다. 따라서 새 노트북이나 iPhone에서는 각각 한 번씩 연결하고 동기화해야 합니다.

앱 프로그램은 새 버전을 배포하면 서비스 워커가 자동으로 받아 두었다가 앱을 다시 열 때 적용합니다. Lichess 연구 내용은 실시간 푸시가 아니라 각 기기에서 `연구 동기화`를 눌렀을 때 변경된 연구만 다시 받습니다. 이미 받은 연구, 앱 화면, Stockfish 엔진은 오프라인에서도 사용할 수 있지만 Lichess 동기화·Opening Explorer·Chess.com 대국 가져오기는 인터넷이 필요합니다.

| 업데이트 대상 | 노트북 EXE | 노트북/아이폰 PWA |
|---|---|---|
| 앱 새 버전 | 새 EXE를 내려받아 교체 | 배포 후 다시 열면 자동 반영 |
| Lichess 연구 수정 | 앱에서 `연구 동기화` | 각 기기에서 `연구 동기화` |
| 로그인·연구 캐시 | 해당 PC에만 저장 | 해당 브라우저/기기에만 저장 |

## 로컬에서 시작하기

Node.js 20 이상이 필요합니다.

```powershell
npm install
npm run dev
```

브라우저에서 `http://127.0.0.1:5173`을 열면 됩니다. Lichess를 아직 연결하지 않아도 샘플 연구로 훈련 흐름을 확인할 수 있습니다.

### Windows EXE

```powershell
npm run desktop:build
```

`release/Opening-Trainer.exe`에 설치가 필요 없는 단일 실행 파일이 생성됩니다. 데스크톱 앱의 연구 캐시는 `%APPDATA%\Opening Trainer\data`에 보존되며, 앱을 다시 실행할 때 Lichess 연결 승인은 다시 해야 합니다. 코드 서명 인증서가 없는 로컬 빌드이므로 Windows에서 처음 실행할 때 SmartScreen 경고가 표시될 수 있습니다.

## 비공개 Lichess 연구 연결

연구를 공개로 바꾸거나 URL을 하나씩 붙일 필요가 없습니다.

1. 앱에서 `Lichess 연결`을 누릅니다.
2. Lichess의 공식 승인 화면에서 연구 읽기 권한을 허용합니다.
3. 앱으로 돌아와 `연구 동기화`를 누릅니다.

앱은 `SaturdayCthuns` 계정과 `study:read` 권한만 허용합니다. 비밀번호는 앱에 입력하지 않으며, 승인 토큰은 앱 코드나 Git 저장소에 포함하지 않습니다. 로컬/EXE용 서버는 외부 네트워크가 아닌 `127.0.0.1`에만 열립니다.

로컬/EXE에서는 승인 토큰을 서버 메모리에만 보관하므로 앱 서버를 다시 시작하면 다시 승인해야 합니다. 이미 동기화한 연구의 PGN과 훈련용 캐시는 `.data/`에 남습니다. PWA에서는 토큰과 캐시를 해당 브라우저의 IndexedDB에 보관하며, 로그아웃하면 토큰만 폐기하고 동기화된 연구는 남겨 둡니다.

## 훈련 규칙

- `연구 → 챕터 → 변형` 순서로 선택합니다.
- 챕터의 `Orientation` 값으로 백/흑을 판별하고 그 색으로 보드를 돌립니다.
- 상대 수는 자동 재생됩니다.
- 현재 포지션에 등록된 다른 레퍼토리 분기도 정답으로 인정합니다.
- 내 차례의 수에 `?` 또는 `??`를 붙인 분기는 피해야 할 예시로 보존하되 정답이나 암기 라인에는 포함하지 않습니다.
- 합법이지만 레퍼토리에 없는 수는 오답으로 기록하고, 정답을 보여준 뒤 직접 다시 두게 합니다.
- 챕터의 모든 라인을 마치면 그 세션에서 틀린 포지션을 다시 풉니다.
- Lichess 원본과 로컬 훈련 데이터는 분리되어 동기화가 원본 연구를 수정하지 않습니다.

현재는 한 훈련 세션 안의 오답 복습까지 지원하며, Chessable식 장기 SRS 일정과 숙련도 진도 저장은 아직 포함하지 않습니다.

훈련 엔진은 표준 체스와 `From Position` 챕터를 지원합니다. 다른 Variant, 방향이 없는 챕터, 또는 백·흑 방향이 섞인 연구는 해당 연구의 동기화 실패 수에 포함됩니다.

## 오프닝 실전 연습

`실전 연습`은 정해진 연구 라인을 외우는 모드와 별개입니다.

- 기본 모드에서는 Lichess Opening Explorer의 실제 게임 빈도에 따라 상대 수가 자동으로 선택됩니다.
- Lichess 데이터가 비어 있거나 요청에 실패하면 브라우저의 로컬 Stockfish로 자동 전환되어 세션이 끊기지 않습니다.
- `엔진 전용`을 고르면 Lichess 로그인이나 네트워크 없이 상대 수 생성과 내 수 판정을 모두 로컬에서 처리합니다.
- 백·흑·무작위 색상과 세션 길이, 상대 레이팅 범위를 고를 수 있습니다.
- 사용자의 합법 수는 먼저 Lichess의 캐시된 엔진 평가를 사용하고, 자료가 없으면 로컬 Stockfish로 판정합니다. 기본 통과 범위는 80cp(약 0.8폰)입니다.
- 실패한 수는 보드에 적용하지 않으며 같은 포지션에서 다시 둡니다.
- 수를 놓으면 판정 중에도 기물이 목적지에 자연스럽게 머물고, 오답일 때만 원래 칸으로 돌아옵니다.

Opening Explorer는 Lichess 연결을 요구하지만 별도의 추가 권한은 필요하지 않습니다. 로컬 엔진은 Stockfish 18의 lite single-thread WebAssembly 빌드를 사용하며, 첫 실행 때 약 7MB의 엔진 파일을 로컬 서버에서 불러옵니다. 이 모드의 결과는 레퍼토리 암기 진도나 오답 복습에 섞이지 않습니다.

Stockfish와 이 프로젝트가 사용하는 WebAssembly 배포판은 GPL-3.0 라이선스입니다. 엔진 원본과 빌드 정보는 [official-stockfish/Stockfish](https://github.com/official-stockfish/Stockfish)와 [nmrugg/stockfish.js](https://github.com/nmrugg/stockfish.js)에서 확인할 수 있습니다.

## Chess.com 실전 레퍼토리 복기

라이브러리의 `실전 레퍼토리 복기`에서는 Chess.com 공개 대국을 내려받아 로컬에 동기화된 Lichess 레퍼토리와 대조합니다.

- 기본 계정은 `Yshaarrj`이며 화면에서 언제든 바꿀 수 있습니다.
- Chess.com 로그인이나 비밀번호는 필요하지 않습니다. 공개 PubAPI의 최근 월별 대국 보관함만 읽습니다.
- Lichess 연결이 만료되어도 이미 동기화된 로컬 연구 캐시로 복기할 수 있습니다.
- 내 수가 준비한 수와 달랐는지, 상대가 연구에 없는 수를 두었는지, 준비한 라인을 끝까지 소화했는지를 서로 다른 결과로 표시합니다.
- 레퍼토리의 마지막 수 이후는 `준비 범위 종료`로 표시하며 오답으로 세지 않습니다.
- `?` 또는 `??`로 표시한 피해야 할 수는 정답 후보에서 제외됩니다.
- 첫 번째 내 레퍼토리 이탈은 로컬 Stockfish로 따로 검사할 수 있습니다. 이 평가는 `책에 있던 수인가`와 `실전적으로 괜찮은 수인가`를 구분하기 위한 보조 판정입니다.
- 원본 Chess.com 대국과 대응하는 Lichess 연구 챕터를 바로 열 수 있습니다.

이 기능은 오프닝 레퍼토리 범위만 복기하며, 중·종반 전체의 전술 실수 분석을 대신하지는 않습니다. Chess.com 공개 API의 범위와 요청 제한은 [Chess.com PubAPI 안내](https://support.chess.com/en/articles/9650547-what-is-the-pubapi-and-how-do-i-use-it)에서 확인할 수 있습니다.

## 명령어

```powershell
npm run dev      # 개발 서버
npm test         # 자동 테스트
npm run build    # 타입 검사와 프로덕션 빌드
npm run build:pwa # GitHub Pages용 정적 PWA 빌드
npm run preview:pwa # PWA 빌드 로컬 미리보기
npm run desktop:build # Windows portable EXE 빌드
npm start        # 빌드된 앱 실행
```

`main` 브랜치에 푸시하면 `.github/workflows/deploy-pages.yml`이 테스트와 PWA 빌드를 실행한 뒤 GitHub Pages에 자동 배포합니다. 다른 저장소 경로로 배포할 때는 `VITE_BASE_PATH`를 `/저장소이름/` 형태로 지정합니다.

로컬 데이터는 `.data/`에 저장되며 Git에서 제외됩니다. `Lichess 연결 해제`는 원격 승인 토큰을 폐기하지만, 이미 받은 비공개 연구 사본은 자동으로 지우지 않습니다. 로컬 사본까지 없애려면 앱을 종료한 뒤 `.data/`를 직접 삭제하면 됩니다.
